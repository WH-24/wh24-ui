# Wowhaus Wiki — ТЗ на доработку мокапов

## Контекст

Папка содержит standalone HTML-мокапы интерфейса внутренней вики Wowhaus. Все 6 экранов сделаны, связаны между собой ссылками. Дизайн-система зафиксирована в CSS-переменных каждого файла (см. `HANDOFF.md` для полного списка токенов).

**Основной принцип:** мокапы — визуальный прототип, не работающий код. Все «действия» — только смена классов и блоков. Никаких реальных запросов, состояний, валидации.

**Текущее состояние папки:**

```
Mocups/
├── hub-mockup.html        — Главная (готов)
├── browser-mockup.html    — Браузер статей (готов)
├── images-mockup.html     — Pinterest-style галерея (готов)
├── search-mockup.html     — Поиск с тремя режимами (готов)
├── article-mockup.html    — Просмотр статьи (готов, нужна проверка)
├── admin-mockup.html      — Админка (готов условно, 4 доработки в HANDOFF.md)
├── HANDOFF.md             — ТЗ для агента в Cursor по доработке админки
└── TZ.md                  — этот файл
```

## Приоритеты

Делать сверху вниз. Каждая задача — отдельный мокап (или модификация существующего), один файл — одна сессия. Не пытаться делать несколько за раз.

## TIER 1 · Критично для презентации

### 1. Edit-mode статьи · `article-edit-mockup.html`

Самый важный пропущенный экран. Сейчас вики показана только в режиме чтения — как редактор работает с контентом, никто не видит. Это убивает половину истории про «живую вики».

**Что должно быть на экране:**

База — это `article-mockup.html`, но в режиме редактирования. Cover-обложка остаётся, но получает hover-overlay «Заменить обложку». Заголовок — кликабелен и редактируется inline. Плашка project-summary — каждое поле редактируется при клике, появляется input.

**Контентная область — ключевая часть:**

- **Hover-handles слева от каждого блока.** При наведении на блок появляются две иконки: `⋮⋮` (drag-grip для перестановки) и `+` (вставить блок ниже). Иконки всплывают слева, не сдвигая контент.
- **Slash-меню.** Когда курсор находится в пустой строке, появляется placeholder «Введите текст или нажмите / для блоков». При нажатии `/` (визуально показать как открытое состояние) — раскрывается dropdown со списком: Параграф, Заголовок 2, Заголовок 3, Список, Цитата, Callout (4 тона), Spec-таблица, Изображение, Галерея, Combo, Embed, Wikilink, Разделитель. Каждый пункт с иконкой слева и keyboard-hint справа.
- **Плавающая панель форматирования.** Возникает над выделенным текстом (показать выделение визуально). Содержит: B, I, U, ~~S~~, `code`, ссылка, wikilink, цвет, очистить. Стиль — тёмная пилюля `#1a1a1a` с белыми иконками, как в Notion.
- **Блок в фокусе** имеет тонкую terra-обводку слева (3px полоска), остальные блоки серые.

**Шапка в режиме редактирования:**

Вместо обычной шапки показать edit-toolbar: слева crumbs-путь, справа — индикатор автосохранения «Сохранено · 12 сек назад» серым, кнопка «Превью» (ghost), кнопка «Отправить на ревью» (primary terra). При клике на «Отправить на ревью» (визуально) показать модал с textarea «Комментарий ревьюеру» (опционально) + кнопки «Отмена» / «Отправить».

**Sidebar-drawer справа (опционально, можно скипнуть):**

Узкий 280px drawer справа: настройки статьи — теги (multi-select), фасеты (по типу статьи), видимость (все / отдел / роли), обложка (загрузить), мета-поля для project-типа.

**Размер файла:** ориентир 50–60 KB.

### 2. Cmd+K палитра · `cmdk-mockup.html`

Заявлена как замена сайдбару во всех экранах. Везде есть пилюля в шапке, но никто никогда не показывал что открывается. Без этого мокапа философия «без сайдбара, всё через палитру» висит в воздухе.

**Что должно быть на экране:**

Затемнённый фон (rgba 26,26,26,0.5 + blur 4px) + центрированный модал 640px ширины, 90vh max-height, 16px от верха экрана.

Структура модала:
- Шапка: input с placeholder «Поиск статей, изображений, действий…», справа `Esc` хинт
- Тело: секции с заголовками `category-h` (uppercase 10px ink-4)
- Подвал: keyboard hints `↑↓` навигация, `↵` открыть, `⌘↵` действие, `Esc` закрыть

**Секции (с примерами наполнения):**

1. **Действия** (4–5 строк) — «Создать статью», «Создать проект», «Создать решение», «Загрузить изображение», иконки слева
2. **Перейти** (5–6 строк) — Браузер, Изображения, Поиск, Регламенты, Закладки, Админка
3. **Недавнее** (4 строки) — последние просмотренные статьи с type-dot слева
4. **Статьи** (заголовок только если в input что-то введено) — топ результатов поиска

**Состояние focused row:** terra-bg, terra-d текст, terra-dot индикатор слева. Стрелки клавиатуры не нужно реально обрабатывать — достаточно показать visual focus на одной строке.

**Опционально:** показать второе состояние в комментариях кода — «когда в input введено что-то». Тогда секции сворачиваются, остаётся только релевантный поиск с подсветкой `<mark>`.

**Размер файла:** ориентир 18–25 KB. Это самый компактный из оставшихся.

## TIER 2 · Желательно

### 3. Article без cover — модификация `article-mockup.html`

Сейчас article-mockup показывает только проектную обложку. Standard-статьи (регламенты, гайды), Solution и обычные Article выглядят иначе:

- Нет cover-обложки
- Заголовок сразу под top-bar, выровнен по контентной колонке
- Нет плашки project-summary
- Type-marker (цветная точка + слово «Стандарт») над заголовком как breadcrumb

Сделать как **отдельный файл** `article-std-mockup.html`. Текстовое наполнение — взять стандарт пожарной безопасности (про него есть данные в admin-mockup compliance-секции). TOC справа остаётся, прогрессбар сверху остаётся, footer с тегами и backlinks остаётся.

**Размер файла:** примерно тот же, что текущий article — около 40 KB.

### 4. Dark mode

Все CSS-переменные ровно для этого. Нужно добавить блок `body.dark { ... переопределённые переменные ... }` в каждый из 6 мокапов и собрать переключатель.

**Тёмная палитра (предложение, можно подбирать):**

```css
body.dark {
  --bg: #15110d;
  --surf: #1f1a14;
  --surf-2: #271f17;
  --surf-3: #312820;
  --ink: #f0ece4;
  --ink-2: #d4cfc4;
  --ink-3: #9a948a;
  --ink-4: #6b665e;
  --bd: rgba(255,255,255,0.08);
  --bd-soft: rgba(255,255,255,0.05);
  --bd-strong: rgba(255,255,255,0.15);
  --terra-bg: rgba(221,103,49,0.15);
  /* terra основной не меняем — он работает на тёмном */
}
```

**Способ реализации:**

Самое дешёвое — toggle на body через JS, кнопка ◐ в шапке, состояние в localStorage не сохранять (мокап). Достаточно сделать в одном файле (например, hub) для демонстрации, в остальные скопировать тот же блок.

**Что проверить руками после применения:**

- Контраст тонких 0.5px границ (могут пропадать)
- Cover-градиенты в article (терракотовый над тёмным фоном — пересмотреть прозрачность)
- Иконки и type-markers (на тёмном тон может перестать читаться)
- SVG-чарты в admin/analytics (background gridlines нужно осветлить)
- Чекбоксы и pending-pills — границы могут пропасть

**Объём работы:** 1–2 часа на адаптацию + проверку.

## TIER 3 · Полировка

### 5. Article project-summary — проверить вёрстку

В прошлой сессии правка применялась через MCP, и из-за таймаутов не уверен, что прошла полностью. Открыть `article-mockup.html` в браузере и проверить:

- Плашка `project-summary` находится **под обложкой**, не overlap с ней
- У `.proj-summary-inner` нет `position: relative`, `z-index`, `box-shadow`
- Margin-top плашки около 18px, она visually отделена от cover

Если что-то не так — поправить точечным `str_replace`.

### 6. Mobile-варианты — пройти все экраны на 375px

Все мокапы имеют responsive CSS (media-queries на 880px и 540px), но целенаправленно никто не открывал на узком viewport. Дешёвая проверка:

DevTools → iPhone 13 mini (375×812) → пройти все 6 экранов → отметить что ломается.

**Типичные кандидаты на проблемы:**

- Браузер: фасетный мега-dropdown может выходить за viewport
- Images: drawer 90vw может перекрывать всё, нет close-кнопки видимой
- Article: TOC tick-rail справа может мешать чтению
- Admin: слишком много колонок в таблицах, sidebar становится горизонтальным — проверить читаемость
- Hub: stats-панель из 4 чисел может слипаться

Фиксы — точечные правки media-queries в конкретных файлах.

### 7. 4 доработки админки (передано в Cursor)

## Дизайн-система — напоминание

**Цвета акцента:**
- `--terra: #dd6731` (основной), `--terra-d: #b8501f`, `--terra-bg: #fbeee5`, `--terra-bd: #e89971`

**Ink (текст):**
- `--ink: #1a1a1a` → `--ink-2: #3d3d3d` → `--ink-3: #7a7a7a` → `--ink-4: #b4b2a9`

**Surfaces:**
- `--bg: #fafaf7` (основной фон), `--surf: #ffffff` (карточки), `--surf-2/3` для вложенности

**Type colors:**
- Проект `#8e3a14`, Стандарт `#444441`, Решение `#0c447c`, Статья `#3c3489`

**Status:**
- `--good`, `--warn`, `--info`, `--bad` — каждый с `-bg` и `-bd` вариантами

**Радиусы:** 5 / 7 / 10 / 12 / 999px (`r-sm` `r-md` `r-lg` `r-xl` `r-pill`)

**Шрифт:** Manrope-only (400/500/600/700), mono для логов и кода.

**Соглашения:**
- 0.5px hairline-границы вместо 1px
- box-shadow редко (только hover карточек и модалы)
- backdrop-filter blur(8px) для прозрачных шапок
- font-variant-numeric: tabular-nums для всех чисел в таблицах
- :focus-visible с 2px terra outline уже задан глобально

## Что не делать

- **Не вводить новые цвета.** Все нужные оттенки уже в `:root`. Если кажется, что нужен новый — почти всегда можно обойтись существующим с другой прозрачностью.
- **Не делать реальную логику.** Нет state management, нет реальных запросов, нет валидации форм. Только toggle классов и видимости блоков.
- **Не плодить новые шрифты.** Manrope-only. Никаких serif для «академичности», никаких декоративных шрифтов.
- **Не использовать emoji в UI.** Иконки — Unicode-символы (✓ ↻ ◇ ▤ ¶ ⌕ ⌘ ↵ и т.п.) или inline SVG. Эмодзи выглядят как Apple на одной OS и Google на другой — ломает консистентность.
- **Не привязывать к React/Vite.** Это standalone HTML. Один файл — один экран, всё inline.

## Порядок работы (рекомендуемый)

1. Открыть текущий проект в браузере, пройти все 6 экранов — впитать стиль.
2. Прочитать `HANDOFF.md` чтобы понять формат и стиль ТЗ.
3. Сделать **Edit-mode** — самая большая и самая ценная задача. Заложить день.
4. Сделать **Cmd+K** — короткая, бодрая. 2–3 часа.
5. Сделать **Article без cover** — клонирование с упрощением. 2 часа.
6. Сделать **Dark mode** — поскольку токены готовы, час на основную палитру и час-два на проверку всех экранов.
7. Полировка: project-summary + mobile.

После всего этого пакет мокапов считается завершённым.
