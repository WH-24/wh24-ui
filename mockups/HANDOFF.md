# Wowhaus Wiki — Admin Mockup · Handoff to Claude Code

## Что это

Standalone HTML-мокап админ-панели внутренней вики Wowhaus (архитектурное бюро).
Все мокапы — в этой же папке `Mocups/`. Связаны ссылками между собой через `href`.
Live-проект (React + Vite) живёт в `/Users/lenivedz/Documents/Codding/deploy/wiki-web` — но мокапы с ним не синхронизированы. Это чистый дизайн-прототип.

**Текущий файл для доработки:** `admin-mockup.html` (~72 KB, single-file).

## Что уже сделано в admin-mockup.html

Полностью реализованы все секции (sidebar + 10 pane-ов):

- **Дашборд** — 4 stat-карточки (с attention-стилем), лента активности, health-блок (admin only)
- **Очередь ревью** — таблица из 7 строк, type-pills, базовые кнопки «Открыть / Опубликовать»
- **Корзина** — таблица из 7 строк с типами, метаданными удаления и сроком хранения
- **Фасеты** — двухколоночный layout (категории слева, значения справа), pending-pills с одобрением для админа
- **Теги** — таблица словаря с активными/ожидающими тегами
- **Регламенты (Compliance)** — двухколоночный с группировкой (По отделам / По категориям / Без), детальной карточкой справа со списком читателей и **assign-панелью «Назначить адресно»** (поиск, выбранные пилюли, список с disabled для гостей, warn-banner)
- **Onboarding** — двухколоночный (маршруты / детальный список шагов с drag-grip), внизу прогресс новичков
- **Аналитика** — 4 stat + SVG-чарт + bar-charts (топ статей, топ запросов, запросы без результатов, теги, compliance отстают)
- **API health** (admin) — 3 sys-stat карточки + таблица из 9 эндпоинтов с GET/POST/PUT/DELETE method-бейджами
- **Логи** (admin) — 15 строк журнала monofont с уровнями info/warn/error/debug
- **Backup** (admin) — 2 info-карточки + история из 10 строк (Авто/Ручной)

Role-toggle М↔А в шапке работает через `body.role-admin` / `body.role-manager`. При переключении на менеджера, если открыта admin-only вкладка — автоматический редирект на Дашборд.

## Соглашения по коду

- **Single HTML file** — никаких внешних JS/CSS, только Manrope из Google Fonts CDN
- **Hairline borders** `0.5px solid var(--bd)` — тонкие, не 1px
- **Box-shadows используются редко** — только на hover карточек или для модалов
- **`backdrop-filter: blur(8px)`** для прозрачных шапок
- **`font-variant-numeric: tabular-nums`** для всех чисел в таблицах
- **`:focus-visible`** с 2px terra outline уже задан глобально
- **JS — минимум**: только toggle классов для визуальной интерактивности. Никаких реальных запросов, никакого state management.
- **role-toggle**: всё, что admin-only, помечено `data-admin` атрибутом — CSS уже скрывает его при `body.role-manager`
- **Все мокапы связаны**: `← В Хаб` и логотип ведут на `hub-mockup.html`

## Стиль интерактивности (важно)

Все «действия» в мокапе — **визуальные**. Это не прототип с реальной логикой. Кнопки могут менять класс или показывать другой блок, но не сохраняют состояние, не делают запросы, не валидируют формы. Это критично — пользователь явно сказал «достаточно визуальности, логики не делай».

Пример хорошей реализации: клик «Вернуть» → раскрылась inline-форма → клик «Отправить редактору» → форма закрылась (можно не закрывать, можно показать toast «Отправлено» — на ваш выбор, но без backend-логики).

## Roles & permissions (контекст)

- **Редактор** — создаёт статьи, отправляет на ревью. Не имеет доступа к админке.
- **Менеджер** — ревьюит, публикует, мерж тегов, compliance, доступы, аналитика. Предлагает значения фасет.
- **Администратор** — всё, что менеджер + одобряет фасеты + Система (API health, Логи, Backup).
- **Гость** — read-only по ссылке, видит только проекты. Не видит регламенты.

В мокапе видны только Менеджер и Админ — toggle переключает между ними. Редактор и Гость — отдельные scope, не часть админки.

## Подсказка по подходу

Если что-то можно сделать **через CSS-only toggle** (`:checked`, `:has()`, sibling combinators) — лучше так, JS только когда без него никак (например, dynamic counter в bulk-bar).

Не плодить новые компоненты — переиспользовать существующие классы (`.rr-btn`, `.ph-btn`, `.seg`, `.modal-*` и т.п.). Если нужны модалы — добавьте сначала shared-стили `.modal-backdrop`/`.modal`/`.modal-h`/`.modal-body`/`.modal-foot` (их сейчас нет в файле), потом используйте.
